Link schemes — allowed vs blocked

The HTML preview's click router routes anchors by URL scheme. This is a visible matrix of every shape it classifies. The actual classification lives in src/lib/url-policy.ts: 

EXTERNAL_LINK_SCHEME = /^(https?|mailto|tel):/i
BLOCKED_LINK_SCHEME  = /^(javascript|file|data|vbscript):/i
Click target Scheme Expected route What you should see
GitHub repo https external Opens in your default browser; iframe does not navigate.
example.com http external Same as above (downgraded HTTP still routes externally).
Email us mailto external Hands off to your default mail client.
Call +1 555 0100 tel external Hands off to the OS dialer (where one is registered).
./01-simple.html (none — relative) workspace Opens that HTML file in a new mdownreview tab.
../markdown/01-gfm-basics.md (none — relative) workspace Opens the markdown sample in a new tab.
#bottom (fragment-only) fragment Smooth-scrolls inside this iframe.
javascript:alert('blocked') javascript blocked Click is preventDefault'd; warn in DevTools; no alert (sandbox would also stop it, but the router blocks first).
file:///…/hosts file blocked Click dropped; warn in DevTools.
data:text/html,… data blocked Click dropped; warn in DevTools.
vbscript:msgbox(1) vbscript blocked Click dropped; warn in DevTools.
leading-newline javascript: javascript (after whitespace strip) blocked The router strips leading whitespace before classifying so "\n\tjavascript:" still hits the blocklist.

What to spot-check

  1. Allowed external rows — clicking opens the OS opener; the iframe never navigates.
  2. Workspace rows — clicking opens a new mdownreview tab pointed at the sibling sample.
  3. Blocked rows — clicking does nothing visible; a HtmlPreviewView: blocked iframe link (blocked-scheme): … line appears in DevTools.
  4. The fragment-only #bottom link smooth-scrolls inside this iframe (you arrived here by clicking it, presumably).
