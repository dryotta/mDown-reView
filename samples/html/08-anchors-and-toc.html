Anchors — in-page TOC + cross-file fragments

The HTML preview's click router (routeLinkClick) classifies hrefs into four buckets:

  • #fragment — scroll to the element with that id inside this iframe.
  • ./other.html#fragment or ../markdown/file.md#fragment — open that workspace file in a new tab and queue the fragment for scroll on load via setPendingFragment.
  • External (https://…, mailto:) — hand off to the OS via openExternalUrl.
  • Anything else (javascript:, file:, data:) — drop with a warn.

Unicode anchor — café

The fragment #unicode-café contains a non-ASCII character. The click handler decodes the URL-encoded form (%C3%A9) before getElementById, so both #unicode-café and #unicode-caf%C3%A9 work.

Cross-file fragments — open another doc and scroll

These open a different file and queue a fragment for the destination viewer to honour:

  • 05-local-css.html#what-to-spot-check — opens the single-stylesheet sample, scrolls to the spot-check section. (Cross-file fragments work when the destination has an explicit id; HTML pages don't auto-slug headings.)
  • ../markdown/11-kitchen-sink.md#heading-anchors — opens the kitchen-sink markdown, scrolls to "Heading anchors". rehype-slug on the markdown side generates the id.
  • ../markdown/01-gfm-basics.md#links — opens GFM basics, scrolls to "Links".
  • ../markdown/01-gfm-basics.md#blockquotes--single-nested-with-content — slug generated from "## Blockquotes — single, nested, with content".
