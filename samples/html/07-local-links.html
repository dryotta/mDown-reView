Local links — opening sibling files in mdownreview

Inside the HTML preview iframe, an anchor href that does not match an external scheme (http, https, mailto, tel) and is not a pure #fragment is treated as a workspace-relative path. The viewer's click handler (routeLinkClick in src/lib/url-policy.ts) resolves it against this file's directory, asserts it stays inside the workspace root, and then calls useStore.getState().openFile(path) to open the file in a new mdownreview tab.

Edge cases — should be blocked

These point outside the workspace root and must be rejected by resolveWorkspacePath; clicking them should not open anything (DevTools console will show HtmlPreviewView: blocked iframe link (outside-workspace): …).

  • ../../../etc/passwd
  • ../../../../Windows/System32/drivers/etc/hosts

What to spot-check

  1. Each sibling-folder link opens that file in a new tab in mdownreview (or focuses an existing tab).
  2. The HTML iframe itself never navigates — its content stays on this page.
  3. The blocked links above produce a console warn and do not open anything.
